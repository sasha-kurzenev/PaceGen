# Эксперимент со звуком гитары

Общий исходный материал — [fixture.json](fixture.json): четыре такта 4/4 при 120 BPM, пауэр-аккорды A5–F5–C5–G5. Для каждого аккорда указана выполнимая аппликатура в стандартном строе. Это специально написанный тестовый рифф, а не часть существующей песни.

Три версии должны получать **одни и те же события** из этого файла: SoundFont, сэмплы чистой гитары и Karplus–Strong. В каждой версии настроить овердрайв, кабинет и одинаковые уровни громкости; delay/reverb/chorus добавить как отдельные переключаемые эффекты. Сравнивать сначала сухой звук, затем общий эффектный микс. Участки с `palmMute` должны звучать заметно иначе, чем `open`.

Перед добавлением каждого стороннего ресурса записать источник, автора, точную лицензию и разрешение на встраивание в офлайн-приложение. Не использовать материал с неясной лицензией. Результаты фиксировать в таблице: размер исходных и упакованных ресурсов, время запуска, средняя/пиковая нагрузка CPU, память, задержка и слышимые дефекты на слабом Android. Экспортировать три WAV с выровненной громкостью и оценивать вслепую по реалистичности и пригодности для рока. Победителя не назначать до прослушивания на телефоне.

## Первый воспроизводимый рендер

`render.py` теперь создаёт три сравнимых варианта без изменения основного приложения. SoundFont воспроизводится FluidSynth 2.6.2, отдельные WAV — простым сэмплером, третий вариант использует Karplus–Strong с собственным возбуждением струны. Все три получают одинаковые ноты, задержку между струнами, силу ударов и длительность. `palmMute` в этом раннем сравнении моделируется короткой огибающей; настоящие сэмплы приглушённых струн и бенды ещё не проверены.

Исходники эксперимента:

| Компонент | Источник и лицензия | Размер загрузки |
| --- | --- | --- |
| Малый FSBS Clean SF2 | [FreePats, версия 2026-08-07](https://freepats.zenvoid.org/ElectricGuitar/clean-electric-guitar.html), CC0 1.0 | 6,60 МБ |
| Те же записи в SFZ + WAV | [FreePats, версия 2026-08-07](https://github.com/freepats/electric-guitar-FSBS-clean), CC0 1.0 | 4,77 МБ |
| Рендер SF2 на компьютере | [FluidSynth 2.6.2](https://github.com/FluidSynth/fluidsynth), LGPL 2.1 | 2,73 МБ |

Сама библиотека FreePats находится также внутри скачанных архивов в `LICENSE.txt`. Для возможного будущего нативного движка есть [TinySoundFont](https://github.com/schellingb/TinySoundFont) под MIT, но этот эксперимент **не измеряет и не проверяет** его звучание и нагрузку. FluidSynth используется здесь только как инструмент сравнения формата SF2; в приложение он пока не добавлен.

Для повторения на Windows нужны Python с NumPy и 7-Zip. Загрузчик проверяет SHA-256 трёх закреплённых архивов и распаковывает их в игнорируемую Git папку `.expo/guitar-spike/`:

```powershell
python experiments/guitar-spike/fetch_sources.py
python experiments/guitar-spike/render.py
```

Если 7-Zip установлен в другом месте, укажите путь через `--seven-zip`. `render.py` сохраняет `riff.mid`, шесть WAV (сухие и обработанные версии), `results.json` и три обезличенные записи `A.wav`, `B.wav`, `C.wav` в `.expo/guitar-spike/output/`. Соответствие букв хранится отдельно в `blind-key.json`, чтобы можно было слушать без названий способов синтеза. Обработанные записи выровнены по общей RMS-громкости, имеют 44,1 кГц, 16 бит, стерео и длину 9 секунд. Цепочка эффектов у всех одинакова: овердрайв, приближённый фильтр кабинета, лёгкие chorus, delay и reverb. Это инженерный прототип кабинета, не импульсная характеристика настоящего усилителя.

Первый рендер прошёл без цифровых перегрузок. Повторный запуск дал те же SHA-256 для всех трёх обработанных WAV. Время рендера на компьютере не сравнивается как показатель эффективности: FluidSynth написан на C, а два других варианта — на Python/NumPy. Сэмплы малого FreePats-банка содержат очень мало энергии выше 6 кГц; по одному спектру нельзя решить, подходит ли это гитарному кабинету, поэтому требуется прослушивание.

До завершения этапа 2 остаются прослушивание трёх вариантов, проверка артикуляций, замер CPU/памяти/задержки на слабом Android и выбор звукового движка. Результат этого шага — работающий протокол сравнения и WAV для оценки, а не решение о включении гитары в приложение.

## Выбор слушателя и проверка на Android

Слушатель выбрал обезличенный вариант **A** — отдельные WAV-сэмплы. Для следующего прототипа берём простой сэмплер и этот CC0-банк; это предварительный выбор по звучанию, а не окончательное решение по нагрузке и артикуляциям. SoundFont и Karplus–Strong остаются сравнительными вариантами.

`build_mobile.py` создаёт полностью самостоятельную HTML-страницу `.expo/guitar-spike/mobile.html`. В ней находятся пять коротких WAV из того же FreePats-банка, нужных тестовому риффу, и Web Audio с овердрайвом, фильтром кабинета, лёгкими chorus/delay/reverb. Файл около 310 КБ. Это ограниченный тест ритм-гитары: сэмплы обрезаны до 0,5 секунды и не подходят для длинных сольных нот.

```powershell
python experiments/guitar-spike/build_mobile.py
node experiments/guitar-spike/check_mobile.mjs
python experiments/guitar-spike/serve_mobile.py
```

Последняя команда раздаёт **только** пробную страницу на порту 8765. Подключите телефон к той же сети и откройте `http://<IP-компьютера>:8765/` в Chrome для Android. Нажмите «Загрузить и играть» и оставьте на несколько минут. Страница показывает число опоздавших нот, максимальную задержку таймера и время декодирования сэмплов. Она продолжит играть после отключения сети, пока открыта, поскольку звук уже встроен в HTML. Если телефон не открывает адрес, проверьте локальную сеть и правила брандмауэра Windows. Остановить сервер можно `Ctrl+C` в его терминале.

Локальный Chromium прошёл проверку: пять сэмплов декодированы, аудиоконтекст работает, за первые 2,2 секунды нет опоздавших нот. Это **не** измерение на Android. Для следующего решения нужны наблюдение на телефоне, время декодирования и счётчик опозданий, а также отдельное измерение CPU/памяти/батареи через инструменты Android. Существующее приложение и его танцевальные жанры пока не изменялись.
